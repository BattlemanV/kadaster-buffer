## 1. Среда и сборка

| Что | Где |
|---|---|
| Qt | `C:\Qt\5.15.2\mingw81_64` |
| Компилятор, make | `C:\Qt\Tools\mingw810_64\bin` |
| CMake | `C:\Tools\cmake\bin\cmake.exe` (в PATH его нет) |
| qmllint, qml.exe | `C:\Qt\5.15.2\mingw81_64\bin` |
| node | есть в PATH, v24 |

```bash
export PATH="/c/Qt/Tools/mingw810_64/bin:/c/Qt/5.15.2/mingw81_64/bin:/c/Tools/cmake/bin:$PATH"
cd build-release && mingw32-make
```

**Кириллица в пути ломает сборку.** AutoMoc CMake под MinGW коверкает путь
(«AutogenInfo.json is not readable»), короткое 8.3-имя CMake разворачивает
обратно. Рабочий обход — `subst K: "<папка проекта>"` и сборка из `K:/`
(кэш cmake тогда хранит `K:/`, без subst пересобрать нельзя).

`build-release/` уже сконфигурирован (`CMakeCache.txt` на месте), заново
звать `cmake` не нужно — только при правке `CMakeLists.txt`.

### Четыре правила сборки, которые ломают больше всего времени

1. **QML зашит в `.qrc`.** Любая правка в `qml/` попадает в приложение
   только после `mingw32-make` (шаг `Generating qrc_qml.cpp`). Запустить
   «из исходников» нельзя. Правка `.qml` без сборки = проверка старого
   кода.
2. **Дистрибутив — только через `tools/make-dist.ps1`** (белый список
   модулей Qt). Новый модуль/плагин Qt без строки в скрипте в установщик
   не попадёт — проверяй запуском `dist\kadbuffer.exe` с урезанным PATH
   (только `C:\Windows\system32`): так видно, чего не хватает.
3. **Запущенное приложение держит exe.** Линковка падает с
   `ld.exe: cannot open output file kadbuffer.exe: Permission denied`.
   Это не ошибка кода. Проверь `Get-Process kadbuffer` и попроси
   пользователя закрыть окно — не убивай процесс сам, там могут быть
   введённые данные и результаты поиска.
4. **ANSI-цвета в выводе make.** Строки вида `[ 14%] \e[34m\e[1mGenerating…`
   не матчатся наивным `grep '] Generating'`. Снимай escape-коды:
   `sed 's/\x1b\[[0-9;]*m//g'`. Иначе покажется, что сборка «ничего не
   сделала». Авторитетный признак — сравнение mtime исходника и
   `qrc_qml.cpp`/`.obj`, а не вывод make.

### Чем проверять, не собирая

* `qmllint <файл>` — синтаксис QML и JS, мгновенно. Гоняй по всем
  `qml/**/*.qml` и `qml/**/*.js` перед каждой сборкой.
  **Важно:** при дисбалансе фигурных скобок `qmllint` завершается
  кодом `-1` И НИЧЕГО НЕ ПЕЧАТАЕТ — легко решить, что сломан сам
  инструмент. Точное место даёт запуск приложения (`Unexpected
  token } в строке N`) либо простой счётчик глубины: для строк из
  одной `}` отступ должен равняться глубине после закрытия × 4;
  первое несоответствие стоит сразу после лишней/пропущенной скобки.
* `node tools/verify-buffer.js` — алгоритм буферной зоны против
  аналитической формулы.
* `QSG_INFO=1` в окружении приложения — печатает реальный рендерер
  (`GL_RENDERER`) и тип цикла отрисовки.

**Зарезервированные слова.** Грамматика QML JS отвергает часть слов,
которые в современном JS свободны: `var transient = ...` даёт
`Expected token 'identifier'`. Туда же `final`, `native`, `volatile`,
`synchronized`, `goto` и прочие future reserved words из ES3. Ошибка
указывает на строку, но причина в имени переменной, а не в синтаксисе
вокруг.

**qml.exe как стенд не работает.** Попытка прогнать JS из `GeoMath.js`
через `qml.exe` с корневым `QtObject` даёт `qml: Did not load any
objects, exiting.` даже на тривиальном файле. Поэтому алгоритмы
отлаживай в node (`tools/`), затем переноси код дословно. Помни про
разницу движков: V8 оптимизирует то, что QJSEngine не умеет (см. §7).

## 2. Кодировки — главная мина проекта

22.10.2026 **14 из 28 текстовых файлов** оказались многократно
перекодированы по схеме «прочитали UTF-8 как CP1251 → сохранили как
UTF-8»: `Main.qml` — 4 прохода, все 8 файлов `qml/components/` — 3,
`cadastralhttp.cpp`/`.h`, `main.cpp`, `CMakeLists.txt`, `README.md` — 1.
Остальные 14 (в том числе все `logconsole.*`,
`appsettings.*`, `tilediskcache.*`, `exportfilehelper.*`, `.iss`, `.qrc`,
`.py`) были в порядке изначально — не правь их вслепую. `Main.qml` (4 прохода) начинался с мусора от
разложившегося BOM, из-за чего **приложение вообще не запускалось**:

```
WARN: QQmlApplicationEngine failed to load component
WARN: qrc:/qml/Main.qml:1:3: Syntax error
```
и выход с кодом `0xC0000374`. Восстановлено, сейчас детектор показывает
«0 проходов» по всем файлам.

### Правила

* Писать **UTF-8 без BOM**. BOM у `.qml` терпим, но при обратном
  преобразовании `U+FEFF` не существует в CP1251 и вырождается в `?`,
  путая любой детектор.
* Если симптом вернулся (`Syntax error` на строке 1) — это кодировка, а
  не синтаксис. Запусти `tools/fix-encoding.ps1` (сухой прогон), посмотри
  колонку `Passes`, затем `-Apply`.
* **Политика выполнения** блокирует `powershell -File`. Зови через
  `&`-оператор в существующей сессии либо
  `powershell -ExecutionPolicy Bypass -File`.
* **PowerShell 5.1 читает `.ps1` без BOM как ANSI.** Собственные
  вспомогательные скрипты с кириллицей он превратит в мусор и упадёт на
  парсинге. Поэтому `tools/fix-encoding.ps1` написан **только ASCII**, а
  диапазоны кириллицы заданы `\u`-кодами. Соблюдай это.
* `Get-Content` без `-Encoding utf8` показывает UTF-8-кириллицу как
  мусор. Это артефакт консоли, а не файла — проверяй байтами
  (`[System.Text.Encoding]::UTF8.GetString([IO.File]::ReadAllBytes(...))`).

### Как устроен детектор

Обратный проход — `строка → байты CP1251 → читаем как UTF-8`. Глубина
подбирается по **числу мусорных биграмм** (`[РС][\u0080-\u04FF]`), а не
по количеству кириллицы: глубоко испорченный текст сам полон строчных
кириллических букв, и критерий «больше кириллицы» выбирает нулевой
проход.

Скрипт не останавливается на первой потере, а считает ВСЕ семь
кандидатов (0–6 проходов) и выбирает лучший по оценке
`ru - 3*junk - 20*bad`, где `bad` — появившиеся `U+FFFD` плюс ПРИРОСТ
числа `?` над исходным. `U+FFFD` возникает, когда проход ушёл
слишком глубоко (правильная кириллица → один байт CP1251 →
невалидный UTF-8 обратно); сам по себе `?` легален — это тернарный
оператор. На чисто-ASCII файлах все проходы дают 0, поэтому
тай-брейк — самый мелкий проход (роундтрип на ASCII идемпотентен).

## 3. `.pragma library` — источник двух одинаковых багов

`qml/components/Cadastral.js` и `GeoMath.js` объявлены `.pragma library`.
Такой модуль **не видит ни контекст QML, ни импорты вызывающего файла**.

Отсюда два реальных дефекта, жившие незаметно:

1. `_httpCall` проверял `typeof cadastralHttp === "undefined"` — а
   `cadastralHttp` зарегистрирован в `main.cpp` через
   `setContextProperty`, то есть библиотеке недоступен. Условие всегда
   срабатывало, запрос не уходил **никогда**. Исправлено: объект HTTP
   передаётся параметром.
2. `parcelFromFeature` проверял `typeof GeoMath !== "undefined"` — а
   `.import` для GeoMath в Cadastral.js отсутствовал (Main.qml импортирует
   оба файла, но это библиотеке не помогает). Контур не вычислялся, и
   **найденный участок выглядел ненайденным**. Исправлено: добавлен
   `.import "GeoMath.js" as GeoMath` в начало файла.

### Правила

* Объекты из `setContextProperty` (`cadastralHttp`, `logConsole`,
  `exportFileHelper`, `appSettings`, `tileDiskCache`,
  `appVersion`) в `.pragma library` **передавай параметром**.
* Другой JS-модуль подключай `.import "X.js" as X` **внутри самой
  библиотеки**, сразу после `.pragma library`.
* **Никогда не глуши код `typeof X !== "undefined"`.** Такая проверка
  превращает отсутствующую зависимость в тихое бездействие. Пусть падает
  с внятной ошибкой.

## 4. Сеть: только через C++, только с заголовками

**QML `XMLHttpRequest` для этих API бесполезен.** Qt вырезает из него
`Referer` и `User-Agent` (оба в списке запрещённых заголовков), а WAF
НСПД без `Referer` отдаёт 403 — проверено автором вживую: без заголовка
403 в 10/10 запросов, с `https://nspd.gov.ru/map?thematic=PKK` — 200 в
10/10. Поэтому весь трафик идёт через `CadastralHttp` (`src/cadastralhttp.*`):

* `get(url, referer, userAgent, timeoutMs)`
* `post(url, referer, userAgent, timeoutMs, body)` — ставит
  `Content-Type: application/json` и `Origin` (берётся из URL, не зашит).

Общая часть — приватный `_send(...)`. Таймаут держит C++ и присылает
ответ со `status 0`; QML-таймеров для этого больше нет.

### Эндпоинты (актуально на 22.10.2026)

| Назначение | Запрос |
|---|---|
| Участок по номеру | `GET /api/geoportal/v2/search/geoportal?query=<номер>&thematicSearchId=1` |
| Соседи | `POST /api/geoportal/v1/intersects?typeIntersect=fullObject` |

Тело `/intersects` — FeatureCollection с одним Polygon в **EPSG:3857** и
`categories: [{id: 36368}]` (слой земельных участков). Формат снят с
собственного веб-клиента НСПД: его инструмент «найти пересечения» делает
ровно такой запрос. Есть также параметр `&CRS=EPSG:4326` у поиска по
номеру — можно просить ответ сразу в градусах (пока не применяется).

### ПКК мертва

`pkk.rosreestr.ru/api/features/1` переадресует на НСПД и отдаёт HTTP 200
с `text/html` — HTML-оболочку веб-карты. Не воскрешай её и не трать
время на «починку» ответов оттуда. Сертификат у хоста к тому же
просрочен; точечное послабление по TLS добавлялось и было **снято**, так
как не покупало ничего. Проверка SSL строгая, и так и должно быть.

### «TLS initialization failed» (27.10.2026)

OpenSSL 1.1.1b в `openssl/` собран MSVC 2017 и требует `VCRUNTIME140.dll` +
UCRT (`api-ms-win-crt-*`). На машине без «Visual C++ Redistributable» он не
грузится — Qt пишет «TLS initialization failed». Рядом с exe теперь лежит
`runtime/` (vcruntime140 14.28 — последняя ветка с Windows 7; UCRT из SDK
10.0.10240 — для Windows 7, в 10/11 система берёт свой). Проверено: в
процессе `VCRUNTIME140.dll` грузится из папки программы.
Не бери vcruntime 14.4x+ (VS 2022 17.10+/2026): Windows 7 они не держат.

### Сертификат Минцифры (27.10.2026)

nspd.gov.ru подписан «Russian Trusted Root CA» (Минцифры). Windows ему из
коробки не доверяет — на машине без сертификатов Госуслуг любой запрос
падал: `SSL: The root certificate of the certificate chain is self-signed,
and untrusted`. Корень встроен в exe (`resources/certs/`, SHA-1
8FF915CC…EC2F, до 2032) и добавляется к системным в `nspdSslConfiguration()`
(src/nspdssl.*) — на КАЖДЫЙ запрос API и тайлов. Проверка НЕ ослаблена:
цепочку, срок и хост проверяет OpenSSL. При SSL-ошибке в консоль пишется
цепочка — так видно антивирус/прокси с подменой сертификатов (их корень
встраивать нельзя — это настройка конкретной машины).
Ловушка: QNetworkAccessManager держит соединение к хосту с SSL-настройками
ПЕРВОГО запроса — менять настройки «для одного запроса» бесполезно.
Подкреплено стендом: sberbank.ru (та же цепочка Минцифры) с CA-списком
без российских корней — ошибка один в один, с встроенным — HTTP 200.
Промежуточный «Russian Trusted Sub CA» не встроен: истекает в 03.2027,
сервер присылает его сам.

### С машины разработки API недоступны

`nspd.gov.ru` и `pkk.rosreestr.ru` отсюда уходят в таймаут (VPN
либо гео-блокировка). `WebFetch`/`curl` тоже не дотянутся.
**Интеграцию проверяет только пользователь**, присылая лог из
приложения. Не выдумывай ответы API и не правь разбор «на всякий
случай» — спроси лог.

## 5. Протокол диагностики

В окне внизу — сворачиваемая панель **«▲ Консоль»** (`LogConsole.qml`,
`expanded: false`), с кнопкой «Копировать». `logconsole.cpp` ставит
обработчик сообщений Qt **до** загрузки QML, поэтому в буфер попадают и
ошибки старта.

Каждый запрос логирует: HTTP-код, размер тела, `Content-Type`, время в
мс. Каждая неудача — причину и фрагмент тела. Статус-строка называет
причину по существу, а не «не найдено».

**Правило: не создавай путь отказа, который ничего не пишет в лог.**
Именно это стоило целого круга отладки — ответ ПКК с не-2xx и пустым
текстом ошибки уходил в молчание, и в логе между запросом и следующим
поиском не было ни строчки.

Две ловушки диагностики, уже исправленные, но помни о классе:

* Флаг `_sourceAnyEmpty` не сбрасывался между поисками и склеивал три
  разных случая в «участок не найден». Заменён на массив причин
  `_sourceDiag`, который чистится в `collect()`.
* Случаи «участков нет», «участок есть, контур не разобран» и «ответ не
  JSON» различаются — иначе баг §3.2 неотличим от честного «нет такого
  участка».

### Отмена устаревших ответов

`_sourceToken` / `_neighborsToken` — счётчики. Колбэк сравнивает свой
токен с текущим и молча выходит, если пользователь успел запустить новый
поиск. Тонкость: `_httpCall`/`_httpPost` при неудачном старте вызывают
колбэк **синхронно**, до присваивания `id`. Поэтому фолбэк написан как
`if (id <= 0 && _sourceToken === token)` — без проверки токена переход к
следующему провайдеру случился бы дважды.

### Где править колонки таблицы

Колонка живёт в шести местах сразу — пропустить одно легко:

1. `Cadastral.parcelFromFeature` — извлечение значения;
2. `_finishNeighbors` → `result.push({...})` — поле в объекте соседа;
3. `headerColumns` — ключ, заголовок, ширина;
4. `_fillTable` → `rowsModel.append({...})` — значение в модели;
5. делегат строки — ячейки расписаны ВРУЧНУЮ, `headerColumns[0..4]`,
   тип форматирования жёстко задан в каждой (число/текст);
6. `exportWord` → `rows.push({...})` и `Reports.js` (`docxRows`,
   `DOCX_HEADERS`, `DOCX_COL_WIDTHS`).

Отчёт проверяется без приложения: `Reports.buildDocx(task)` в node, части
упаковать в zip и открыть python-docx. Регулярки сверяй и в движке Qt
(`qml.exe` с QML_XHR_ALLOW_FILE_READ=1, вывод через encodeURIComponent —
stderr qml.exe не в UTF-8): `\b`/`\w` не знают кириллицы, а
`replace(/\B(?=(\d{3})+(?!\d))/g)` в V4 вставляет разделитель дважды.

### Повторы при временных ошибках

В цепочке провайдеров остался только НСПД, поэтому разовый `HTTP 500`
раньше обрывал весь поиск (`attempt >= length` срабатывал сразу).
Теперь на статус `0` или `5xx` делается **один** повтор того же
провайдера: `_sourceRetry` / `_neighborsRetry`, сбрасываются в
`collect()` и после успешного ответа. Повтор пишется в лог.

### Известный тестовый участок

Проверяй на реальном участке из своей работы (номер в репозиторий не
кладём). Ожидаемо: НСПД отдаёт Polygon/MultiPolygon в EPSG:3857;
`/intersects` возвращает больше участков, чем остаётся после фильтра.

## 6. Геометрия

Всё в `qml/components/GeoMath.js`. Локальная равнопрямоугольная проекция
`projectLocal` вокруг центроида; на масштабах участка её погрешностью
модуль пренебрегает сознательно.

| Функция | Назначение |
|---|---|
| `cadastralGeometryToRing` | ответ источника → `[{lat,lon}]`; распознаёт EPSG:3857 по `crs` или по `|x|>180` |
| `webMercatorToLatLon` / `latLonToWebMercator` | пара взаимно обратных (ошибка туда-обратно ~3e-14 градуса) |
| `minDistanceRingsM` | минимальный зазор между контурами, O(n·m) по парам рёбер |
| `centroidOfRing` | площадной центроид (шнур Гаусса), для румба |
| `bufferRingM` | буферная зона — настоящий многоугольник по контуру |
| `simplifyXY` | упрощение Дугласа—Пекера |

### `bufferRingM` — самое хрупкое место

Построение: **поле знаковых расстояний → marching squares на уровне
`meters` → сшивка сегментов в кольцо → упрощение**. Смещение вершин по
бисектрисам отвергнуто: на вогнутых углах даёт самопересечения, а
участки сплошь Г- и U-образные.

Проверять **только численно**, `node tools/verify-buffer.js`: на выпуклых
контурах площадь обязана совпасть с `A + P*buf + pi*buf^2` (сейчас
расхождение менее 1%). На вогнутых формула завышает — это норма, вогнутые
углы не дают полного кольца.

Самые опасные ветки — **седловые случаи 5 и 10**. В случае 10 уже был
баг: одна ветка вырожденная, вторая перепутана. Тесты на выпуклых
контурах его не ловят, потому что седловых точек там не возникает
вообще. Поэтому в `verify-buffer.js` есть U-образный контур с буферами
6/18/30 м: при малом буфере выемка открыта, при больших зоны плеч
смыкаются. Любая правка marching squares — прогонять его.

### Что уходит в запрос, а что рисуется

* Рисуется — `bufferRingM`, **по одному кольцу на каждый исходный
  участок**. Состояние: `bufferRings` (массив колец), отрисовка
  `Repeater { model: bufferRings.length }`, построение в
  `_onSourceFound` циклом по `sourceRings`. Одним кольцом объединённую
  зону не выразить: у разнесённых участков зоны не связаны, а
  объединение полигонов требовало бы булевых операций, которых в
  проекте нет.
* Если `bufferRingM` не построил ни одного кольца (вырожденный контур),
  подставляется прямоугольник `boundsToRing(bufBounds)` — иначе зона
  поиска стала бы невидимой. В лог пишется
  `Буферные зоны: построено N из M, X мс` — это и есть измерение
  стоимости на настоящем движке, не экстраполяция из node.
* В `/intersects` уходит **расширенный прямоугольник bbox**. Намеренно:
  прямоугольник заведомо накрывает буфер, то есть исключает пропуски, а
  буферный многоугольник из-за дискретности сетки местами проходит на
  сантиметры внутри истинного и мог бы потерять участок на границе.
  Окончательный отбор всё равно по `minDistanceRingsM`.

### Кадастровый номер

Четыре группы: `регион:район:квартал:участок`. Регулярка — единственная
константа `CAD_NUM_RE` в `Cadastral.js`:

```js
/\d{1,3}:\d{1,3}:\d{1,8}(?::\d{1,8})?/
```

Было `/\d{2}:\d{2}:\d+/` — три группы, из-за чего номер **обрезался до
кадастрового квартала** (`38:00:000000` вместо `38:00:000000:100`) и в
таблице, и в отчёте. Шаблон был продублирован в двух ветках, что и
позволило багу дожить. Не дублируй его снова.

## 7. Эффективность: что измерено

Не оптимизируй это приложение «на глаз» — предыдущая попытка дала
замедление.

* **Геометрия не узкое место.** Сбор 17 участков — 1623 мс, из них почти
  всё сетевой запрос. Фильтрация незаметна.
* **Предложенные оптимизации `minDistanceRingsM`** (предфильтр по bbox,
  единая проекция вместо пересчёта на каждого соседа, отказ от
  аллокаций в `_segSegDistXY`) при замере на 100 участках × 40 вершин
  дали **x0,9 — замедление**, а предфильтр отбрасывал 6 из 100. V8 сам
  устраняет эти аллокации. Под QJSEngine результат может отличаться, но
  замерить его нечем (§1), а экономить там нечего.
* **Отрисовка на GPU**: `GL_RENDERER: Radeon RX 560 Series`, OpenGL 4.6,
  threaded render loop. Программный `opengl32sw.dll` (20 МБ) не
  задействован — он лежит в дистрибутиве как фолбэк для машин без
  драйверов, и это правильно.

Осознанно не тронуто, потому что неизмеримо на 13–17 строках: пересоздание
делегатов заголовка в `_applySort` (`model = 0; model = N`) и `Math.cos`
на каждой вершине в `projectLocal`. Браться, только если появятся сотни
соседей — и тогда сначала замер.

## 8. Несколько участков-оснований

С 22.10.2026 приложение поддерживает ввод **нескольких** кадастровых
номеров через запятую, точку с запятой или новую строку:

```
38:00:000000:100, 38:00:000000:300
```

### Состояние (Main.qml)

| Было | Стало |
|---|---|
| `sourceNumber: ""` | `sourceNumbers: []` |
| `sourceRing: []` | `sourceRings: []` |
| `sourceCentroid: null` | `sourceCentroids: []` |
| `bufferRingDisplay: []` | `bufferRings: []` |
| — | `sourceProviders: []` |

### Алгоритм `collect()`

1. Разбивает `numberField.text` по `/[,;\n\r]+/`, тримит, фильтрует пустые.
2. Запускает последовательный поиск каждого номера через `_requestSource`.
3. `_onSourceFound` аккумулирует каждый найденный участок в массивы.
4. Когда `_sourceCollectedCount === _sourceTotal` — вычисляется
   **объединённый bbox** всех `sourceRings`, расширяется на `bufferMeters`,
   и для КАЖДОГО участка строится свой буферный полигон
   (`GeoMath.bufferRingM`) в `bufferRings`.
5. Бounding box уходит в `/intersects` как обычно.

### Фильтрация соседей (`_finishNeighbors`)

Для каждого найденного участка вычисляется **минимальный зазор до
ЛЮБОГО** из `sourceRings` (перебор всех `sourceRings`, `min()` по
`minDistanceRingsM`). Если `minGap <= buffer` — участок включается.
Исходные номера отбрасываются по проверке `sourceNumbers.includes()`.

### Румб

Вычисляется от **ближайшего** исходного участка: перебор
`sourceCentroids`, расстояние Хаверсина, берётся центроид с минимальным
расстоянием → `rumbBetween` от него до центроида соседа.

### Карта

Четыре слоя, все через **`MapItemView`**: буферные зоны, исходные
участки, соседи, подписи номеров.

#### Три ловушки QtLocation, на которых карта молча пустеет

1. **`Repeater` НЕ добавляет элементы на `Map`.** Элементы, созданные
   `Repeater`, в список элементов карты не попадают — ни ошибки, ни
   предупреждения, карта просто пустая. Для модельной отрисовки годится
   только `MapItemView` с `delegate:`. На этом уже сгорел один круг:
   `sourceRings` и `bufferRings` были объявлены через `Repeater`.
2. **В делегате `MapItemView` бери `modelData`, а не `массив[index]`.**
   `window.neighbors[index]` давало `undefined`: `visible` получал
   `undefined` (`Unable to assign [undefined] to bool`), а `path` с
   проверкой `if (!d) return pts` возвращал пустой массив — полигон из
   нуля точек. Приводи `visible` к логическому через `!!(...)`: иначе
   привязка ломается молча и свойство остаётся со старым значением.
   Индекс через `neighbors.indexOf(modelData)` НЕ работает: делегат модели из
   JS-массива получает в `modelData` КОПИЮ объекта, `indexOf` даёт -1
   (проверено 26.10.2026 в qml.exe и для MapItemView, и для Repeater —
   из-за этого клик по карте молча ничего не делал). Ищи по ключу —
   кадастровому номеру (`_selectRow(num)`, `_mapClicked(num, mods)`).
3. **`_fitToBounds` ждёт `{south, north, west, east}`**, а
   `GeoMath.ringBbox` отдаёт `{minLat, maxLat, minLon, maxLon}`.
   Передать первое вместо второго — получить `NaN` в центре карты:
   слои отрисуются и через миг исчезнут, потому что карта уедет в
   никуда. Симптом «границы появляются на секунду и исчезают» — это он.
   `_fitToResults()` теперь переименовывает поля явно.

`_fitToResults()` объединяет bbox ВСЕХ колец обоих массивов через
локальную `acc()`. Раньше bbox затравливался одним кольцом буфера и
терял остальные — карта обрезала часть зоны по краю.

#### Подложка НСПД (с 26.10.2026)

Карта на плагине `itemsoverlay` (сам ничего не рисует), подложку рисует
`nspdTiles` в Main.qml: XYZ-тайлы
`https://nspd.gov.ru/api/aeggis/v4/235/wmts/{z}/{x}/{y}.png` (адрес снят
пользователем из веб-карты НСПД), загрузка — `TileDiskCache` с Referer НСПД
и таймаутом 20 с. Отказы — в консоль («Тайл не загружен: … HTTP …»).
С машины разработки тайлы уходят в таймаут — это норма (§4).
Почему не плагин "osm" + custom.host: CARTO без ключа ставит водяной знак
"API KEY REQUIRED", а OSM через этот плагин молча не грузится (сервер
отвечает 200 — проверено curl и XHR), Referer плагин не шлёт.
Нужна ли тайлам Referer, не проверено; максимальный уровень тайлов НСПД —
тоже (`maxTileZoom: 19`, глубже тайлы растягиваются).

Исходные участки — синие с косой штриховкой (`GeoMath.hatchSegments` →
`sourceHatch` → MapPolyline). Штриховка пересчитывается явно в
`_buildSourceHatch()`: `sourceRings` пополняется `push`, без уведомлений.

#### Номер участка `no` (с 26.10.2026)

`neighbors[i].no` — постоянный номер (по зазору, ближайшие = 1),
присваивается в `_finishNeighbors`. Он подписан на карте вместо
кадастрового номера и стоит в колонке «№» таблицы. `_applySort` его
больше НЕ перенумеровывает — иначе номер на карте разойдётся со строкой
таблицы. Клик по строке → `_rowClicked`, по карте → `_mapClicked` (оба — по номеру).
MouseArea полигона — прямоугольник вокруг него, поэтому `onPressed`
пропускает клик, если точка вне контура (`_ringContainsScreen`). MouseArea
подписи — внутри плашки: у MapQuickItem нулевой размер. Подпись ставится в
`label` (`GeoMath.labelPointInBuffer`: внутри участка И внутри буфера), а
не в центроид — у дороги центроид лежит за зоной, и казалось, что
участок попал в список зря.

Карта и таблица — в `SplitView`, ширина таблицы тянется мышью.

Цвета и штриховка слоёв — в легенде карты (клик по значку — палитра,
«▨» — штриховка; у буфера штриховки нет). Хранятся через
`appSettings.value/setValue` под ключами `layers/*` —
`%APPDATA%\KadBuffer\KadBuffer.ini` (свой файл с 1.2.0).
Штриховка соседей считается только при включённой галке
(`_buildNeighborHatch`) — это тысячи MapPolyline.

Консоль (`LogConsole`) скрыта, открывается по F12 — других каналов
диагностики нет, не удаляй её.

#### Виды участков, выбор и удаление, экспорт карты (26.10.2026)

* Вид участка `kind` (`Reports.parcelKind` по назначению) задаёт узор
  штриховки: `Reports.PARCEL_KINDS[].angles` → `GeoMath.hatchSegments(ring,
  step, angle)` для каждого угла. Расшифровка — в легенде (`kindsPresent`),
  видна при включённой штриховке «Участков в зоне».
* Таблица: колонка «Площадь, м²» (`area`, сортируемая). Выбор строк —
  `selectedNumbers` (по кадастровому номеру), Ctrl/Shift+клик, Ctrl+A,
  Esc; Delete или кнопка «Удалить» убирает участки из `neighbors` (карта,
  таблица, отчёт) в `removedNeighbors`; «Вернуть» — обратно. Номера `no`
  после этого пересчитываются (`_renumber`). Горячие клавиши выключены,
  пока фокус в полях ввода, — иначе Delete удалял бы участки при наборе.
* `_fillTable` теперь применяет текущую сортировку (раньше оставлял
  порядок neighbors, а стрелка в шапке показывала другую сортировку).
* «Экспорт карты» — `mapFrame.grabToImage` в двойном разрешении → PNG в
  папку выгрузок (`<номер> буфер N м.png`).

#### Многоконтурные участки (26.10.2026)

НСПД отдаёт многоконтурный участок (гаражный кооператив, линейный
объект) как MultiPolygon. Раньше `cadastralGeometryToRing` брал только
`coordinates[0][0]` — первую часть, и участок 38:00:000000:400 (большой
кооператив) рисовался и мерился одним мелким контуром. Теперь
`cadastralGeometryToRings` → `parcel.rings` (все внешние контуры; отверстия
не учитываются), `parcel.ring` — самый большой. Исходный участок кладёт в
`sourceRings` все части (буфер вокруг каждой), сосед — зазор до ближайшей
части, подпись — в ней же, центроид для румба — взвешенный по площади
(`centroidOfRings`). Карта рисует `neighborParts` — по полигону на часть.

Экспорт карты спрашивает путь системным диалогом
(`exportFileHelper.chooseSavePath` → Win32 `GetSaveFileNameW`, comdlg32 —
без Qt Widgets/Dialogs); папка запоминается в `export/mapDir`.

#### Стенд интерфейса без НСПД (26.10.2026)

`tools/qmltest/tst_main.qml` — Qt Quick Test: грузит НАСТОЯЩИЙ Main.qml с
заглушками C++-объектов, подаёт вымышленные участки (в т.ч. многоконтурный)
через `_onSourceFound`/`_finishNeighbors` и кликает мышью по карте, подписям,
исходному участку, заголовку таблицы; проверяет удаление/возврат и экспорт.
Запуск из корня (Git Bash):
`PATH="build-release:/c/Qt/5.15.2/mingw81_64/bin:$PATH" qmltestrunner.exe -input tools/qmltest/tst_main.qml`.
Пересборка не нужна — Main.qml читается с диска. Гоняй после правок QML.

Что стенд уже поймал:
* `sourceRings.push(...)` не уведомляет привязки — слой исходных участков
  на карте был ПУСТ (видна была только штриховка), клик по исходному
  проваливался. Массивы-модели — только присваиванием нового массива.
* `_fitToBounds` ставил центр до масштаба: при мелком масштабе Qt зажимает
  широту центра в 0. Порядок — сначала zoomLevel, потом center.

Буфер: `GeoMath.bufferRingsM(sourceRings, buf)` — одна зона вокруг
объединения всех исходных контуров (поле расстояний = минимум по контурам).
Ориентация после сшивки: внешний контур по часовой (площадь < 0), дыры
отбрасываются.

#### Подсветка — по номеру, не по индексу

`highlightNumber` (строка), а не `highlightIndex`. Индекс здесь
двусмыслен: у карты это позиция в `neighbors`, у таблицы — номер строки
`rowsModel`, и после `_applySort` это разные вещи. Со старым
`highlightIndex` клик по отсортированной таблице центрировал карту на
чужом участке.

### Экспорт

`source_number` → `source_numbers` (массив строк), `provider` →
`sourceProviders.join(", ")`.

С 1.2.0 (26.10.2026) экспорт — только Word, без Python: `exportWord` в
Main.qml собирает задание, `Reports.buildDocx` строит XML частей .docx
(форма раздела СЗЗ: абзац о ближайших нормируемых территориях по 8
румбам + таблица всех участков с площадью, по площади от большей к
меньшей), `exportFileHelper.writeZip` (C++, deflate через qCompress +
CRC32) пакует их в zip. Нормируемость — по ключевым словам назначения
(`NORMED_KINDS`), абзац черновой. Excel-выгрузка убрана по просьбе
пользователя.

`extractAreaM2` больше НЕ угадывает гектары по величине числа (≤ 100 → га
превращало гаражи 24 м² в 240 000 м²); в га считается только `area_ha`.
Единицы полей НСПД по логу не сверены.

### Ловушки

* Формы единственного числа (`sourceRing`, `sourceCentroid`,
  `sourceNumber`) уже удалены полностью — `grep` даёт 0 вхождений.
  А вот **`sourceProviderName` остался мёртвым**: объявлен свойством и
  нигде не используется (его заменил `sourceProviders`). Там же мёртвая
  `var plural` в `_onSourceFound`.
* **Лишняя `}` после `MapItemView` сломала всю загрузку QML.** Блок
  «Легенда» был добавлен ПОСЛЕ закрывающей скобки `Map`, но с
  отступом «внутри» — вся вложенность съехала на уровень, файл
  закончился глубиной −1, и приложение падало с `Unexpected token }`.
  Всегда проверяй запуск после правки разметки, а не только сборку:
  сборка такой дефект НЕ ловит (QML разбирается в рантайме).
* `_fitToResults()` теперь объединяет bbox всех `sourceRings` +
  `bufferRingDisplay`. Если убрать один из блоков — карта будет
  обрезать часть результатов.

## 9. Открытые вопросы

* Лимит ответа `/intersects` неизвестен. В статусе печатается, сколько
  участков пришло от источника; подозрительно круглое число — повод
  проверить обрезку на стороне НСПД.
* `&CRS=EPSG:4326` у поиска по номеру позволил бы получать градусы и
  убрать зависимость от эвристики `|x| > 180` в
  `cadastralGeometryToRing`. Не применено: не хотелось менять рабочий
  код посреди отладки другого места.
* **Имена полей назначения у НСПД не подтверждены.** `extractPurpose`
  в `Cadastral.js` перебирает `PURPOSE_KEYS` (разрешённое использование),
  затем `CATEGORY_KEYS` (категория земель), затем ищет по шаблону
  ключа. Фактические атрибуты первого соседа пишутся в консоль
  (`Cadastral.dumpAttrKeys`) — сверь по ним и сузь список. Не угадывай
  имена без лога.
* Площадь на экране не показывается, но идёт в отчёт Word (`area_m2`).
* Установщик 1.2.0 (26.10.2026): около 16 МБ, `dist` около 66 МБ.
  imageformats не входят (PNG встроен в QtGui). D3Dcompiler_47 ВХОДИТ —
  ради Windows 7/8 (в Windows 10/11 он есть в System32, там можно без него).
  ANGLE в Qt-сборке MinGW ищет компилятор в порядке d3dcompiler_43 → _47.
  Установка на чистой машине не проверялась. ISCC:
  `%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe` (не в PATH).
  `[InstallDelete]` в .iss убирает при обновлении остатки 1.0/1.1
  (Python, opengl32sw.dll, лишние модули Qt).

## 10. Как себя вести

* Прежде чем объяснять поломку сетью или форматом API — проверь §2 и §3.
  Оба крупных дефекта этого проекта оказались внутренними, хотя выглядели
  как «сервис не отвечает» и «такого участка нет».
* Утверждения о поведении API проверяй логом пользователя, а не
  догадками. Что не проверено — помечай как непроверенное, в коде и в
  ответе.
* Перед правкой исходников делай резервную копию: каталоги
  `_backup_encoding_*` в корне — от восстановления кодировок 22.10.2026,
  их можно удалить, когда уверенность появится.
* Массовую перезапись файлов среда может заблокировать как необратимую.
  Делай группами с проверкой после каждой, как в
  `tools/fix-encoding.ps1`.
